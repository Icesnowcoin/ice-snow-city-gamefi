# Ice Snow City 全局完整性与服务器部署前复盘报告

**复盘日期：** 2026-08-29  
**复盘对象：** `ice_snow_city_agent` 当前代码库与最近稳定版本  
**复盘范围：** 前端游戏入口、3D 渲染、认证与路由、后端和数据库、实时交易通知、模拟 Web3 合约边界、测试构建、资产交付和服务器发布条件。

## 一、执行摘要

当前项目已经达到“**可运行的代码候选版本**”，但还没有达到“**可以无条件面向真实用户和真实资金开放的主网生产版本**”。前端具备 GameHub 主场景、任务与建设交互、商城与背包、房地产放置、NPC/角色预览、WebGL 降级、认证入口、钱包与交易 UI，以及 local-hardhat 模拟交易历史和全局通知中心。后端具备 Manus OAuth、tRPC、数据库模板、存储和通知基础设施；模拟市场流程已验证 SELL、BUY_OFFER、取消 nonce、EIP-712 签名恢复和 60/40 手续费拆分。

本次全量质量门禁得到 **170 个测试文件、2063 项测试全部通过**，生产构建通过。一次性 TypeScript 检查在当前沙箱 384 MB 堆限制下因 JavaScript heap OOM 退出，因此不能把类型检查标记为通过。开发服务仍可运行，但日志存在外部 BSC RPC 轮询的 TLS 证书域名不匹配错误；这不影响 local-hardhat 模拟流，却意味着生产链上事件监听不能直接沿用当前运行状态。

最重要的发布结论是：**可以继续部署一个受控的演示/测试环境，但不应在真实合约、真实资产、真实资金和生产写入尚未完成审计与验证前开放主网交易。**

## 三、游戏完整性复盘

### 3.1 已形成的游戏闭环

用户从开场页进入认证流程后，默认进入 GameHub，而不是停留在个人中心。GameHub 已经承载建设、任务、房地产/房屋放置、商城、背包、收益收取、升级、社交、NPC 和角色预览等主要入口。商城侧已经覆盖搜索、分类、排序、收藏、详情、相关推荐、分享链接、购物车和移动端 BottomSheet 等交互。个人资料侧已经形成 NFT 概览、主页背景、分享海报、二维码、社交分享和排行榜等产品方向。

这说明项目已经有较完整的“**界面级可玩闭环**”。但是，代码级闭环和运营级闭环仍有区别。需要继续验证每个关键动作是否在刷新、重新登录、跨设备和异常网络后保持一致，尤其是建设收益、背包物品、房屋坐标、NFT 所有权、交易状态和通知历史。

### 3.2 当前不能视为完成的游戏层能力

第一，真实高保真资产未进入项目资产交付链。项目规范要求大型媒体不直接放入项目目录，而是经由 WebDev 存储引用；当前扫描未发现可交付的 GLB、GLTF、MP4、WAV 或大型 PNG/JPG 文件。因此角色、建筑、环境和开场动画在代码层有接入框架，但不能证明部署后会展示最终美术版本。

第二，长周期经济系统还需要独立的数值验收。历史需求要求将收益大幅下调并以长期运营为目标；当前代码和文档中存在多套模拟经济与展示参数，必须建立唯一的生产参数来源，验证离线收益、升级收益、回收价格、库存消耗和资产价格不会因前端状态重置或重复提交而膨胀。

第三，真实用户数据的持久化边界需要逐项打通。当前项目有数据库基础设施，但很多历史功能仍以模拟或前端状态表达。部署前必须确认哪些字段写入数据库、哪些字段来自链上、哪些字段只能从索引服务重建，并为冲突、幂等和回滚设计明确规则。

## 五、质量与安全门禁结论

### 已通过或基本具备的门禁

当前全量 Vitest 结果为 **170 个测试文件、2063 项测试通过**。最近的通知中心和批量重试定向测试验证了历史记录、状态筛选、详情、复制日志、失败重试、批量进度、成功/失败/跳过统计和状态事件去重。生产构建在受控内存配置下通过，开发服务也能正常运行。

Draft 合约边界已在文档和适配层中明确，local-hardhat `chainId 31337` 的模拟流程验证了市场订单、EIP-712、取消 nonce 和 60/40 费用拆分。该结果证明模拟逻辑可重复，不证明合约已经过第三方审计，也不证明生产地址、字节码、流动性、权限和主网 RPC 正确。

### 未通过或尚未完成的门禁

一次性 TypeScript 检查在 384 MB Node 堆限制下因 OOM 终止，退出码不是代码错误，但结果必须标记为“未完成”，不能标记为通过。当前历史 TODO 仍有 36 项未完成，其中相当部分是既往阶段保留的外部同步、GitHub 清洁分支、真实资产、审计和资源门禁记录；这说明项目的任务账本需要整理，不能把“历史条目未勾选”简单等同于每项都仍是代码缺陷。

开发日志出现 BSC RPC 轮询的 TLS 证书域名不匹配错误。此类错误属于运行环境/外部端点问题，需要在生产部署前修复或明确关闭真实链上监听。当前 local-hardhat 模拟测试通过，不应覆盖这一真实网络风险。

## 六、上线建议顺序

第一阶段应继续保持“模拟/只读发布”：部署当前代码用于产品验收、移动端体验、WebGL 降级、开场流程、GameHub、通知中心和性能观察，但在界面上明确 local-hardhat 和 Draft 状态，不接受真实资金或真实链上写入。

第二阶段完成生产基础设施：锁定域名和 OAuth 回调，迁移并验证数据库，配置生产 secrets，解决 RPC/索引器 TLS 问题，建立日志、告警、备份、恢复和限流；随后在更高内存 CI 中完成 TypeScript 检查，并执行真实设备矩阵测试。

第三阶段完成 Web3 发布门禁：第三方审计、修复复审、合约源代码与字节码验证、多签/权限/暂停方案、测试网部署和回放、确认数与重组策略、真实索引器一致性测试。只有这些门禁通过后，才可讨论开放受控主网写入。

第四阶段完成资产与运营门禁：接收真实 GLB/PBR 与开场媒体，完成哈希和版本登记，测量低端设备内存和首屏时间，补齐内容运营、隐私条款、风控和客服流程，然后进行小规模灰度发布。

## 七、最终结论

> **当前项目可以作为受控演示/测试环境继续运行，但还不能被证明为经过主网安全审计、真实资产交付、生产数据恢复和移动设备验收的完整商业游戏。**

部署到服务器以后，最需要补齐的不是普通 UI 小功能，而是四类发布级事实：**真实资产是否存在并被正确加载、真实合约是否审计并锁定权限、生产数据和外部服务是否可恢复可观测、真实移动设备和异常网络是否通过验收**。在这些事项完成前，建议继续使用模拟链和只读边界，避免把“构建成功”误解为“主网可安全运营”。
