# 任务执行稳定性审计

## 审计结论

本轮“陷入循环”并非开发服务器无限重启。当前开发服务器保持单一 `tsx watch server/_core/index.ts` 进程，浏览器控制台没有新增 error/exception/timeout，页面与认证请求返回 200。主要风险来自两类可重复触发因素：完整 Vitest 在失败或超时后被反复启动，导致验证过程看起来循环；以及 TradingCenter 的余额刷新 effect 依赖每次渲染都可能变化的 `marketplace` 返回对象，余额状态更新会触发再次请求。

## 已采取措施

TradingCenter 的 effect 依赖已从整个 `marketplace` 对象收窄为稳定的 `marketplace.getISCBalance` 回调。组件同时移除了模拟行情、示例订单、占位 marketplace 地址、示例 listingId 和占位 NFT 地址；缺少真实合约或挂单数据时只显示诚实空状态，并禁用交易操作。新增安全边界测试 2/2 通过。

验证流程改为单模块、单次、显式 `--run` 执行；完整套件不再在前一轮未退出时并发启动。长时间测试必须通过 shell 超时包裹，并在超时后检查进程而不是立即重复启动。当前仅保留一个开发服务器进程，生产构建在 120 秒上限内完成。

## 当前风险与边界

完整 Vitest 仍存在独立模块失败，不能将其误判为产品已经全部通过。Babylon.js、异步 hook 和真实链上交互需要单独的测试隔离或凭据，不在本轮安全降级范围内。生产构建通过，但仍有大型前端 chunk 警告，属于性能优化事项而非执行循环故障。
