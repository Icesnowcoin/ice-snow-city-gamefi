# Ice Snow City 美术设计工具包

> 版本：2026.08｜适用平台：移动端横屏 16:9｜视觉方向：现代冰雪商业都市、2.5D 伪3D、半写实卡通｜状态：生产规格与验收模板已建立，真实 GLB/纹理/动画文件仍待资产团队交付。

## 一、项目视觉 DNA

Ice Snow City 的核心画面不是战争或冷兵器幻想，而是一个长期运营的现代商业帝国。所有场景应围绕“冰雪环境中的现代城市生活、商业建设和社会协作”展开。角色使用改良 Q 版比例，头部约占身高三分之一，服装采用现代商务、都市街头和职业制服语言；建筑使用玻璃幕墙、金属、混凝土、冰晶和暖色室内光，避免中世纪城堡、武器、铠甲和战斗化视觉符号。

主画面使用 2.5D 伪3D/等距构图作为低负载和移动端阅读基准，真实 3D 资产进入运行时前必须通过项目内 `assetManifest`、PBR/LOD/碰撞体、纹理预算和动画导出门禁。没有真实文件时，程序化模型或 Canvas 回退必须显式显示“待导入/程序化回退”，不得冒充高保真资产。

| 视觉层 | 规范 |
|---|---|
| 主冷色 | 天空蓝 `#1E90FF`、深蓝 `#0F3460`、冰雪白 `#F8F9FA` |
| 暖色强调 | 金色 `#FFD700`、橙色 `#FF8C42` |
| 功能色 | 成功 `#4CAF50`、警告 `#FF9800`、错误 `#F44336` |
| HUD 背景 | 页面 `#0F1419`、卡片 `#1A1F2E`、正文白色 |
| 光照 | 主光 45° 冷白，环境蓝光，低强度暖色补光 |
| Logo | 统一使用官方 ISC Logo 组件；Logo 不与装饰雪花混用，不重新绘制或变形 |
| 交互 | 触控目标至少 44px；关键弹窗、抽屉和 Toast 使用短促、可中断动画 |

## 四、角色与 NPC 设计卡模板

每个角色必须提交完整全身设计，而不是只有头像。设计卡至少包含：角色 ID、姓名/职业、社会身份、年龄段、身高比例、脸型、发型、肤色、眼型、服装层级、配色、配饰、动作列表、表情列表、材质说明、背景故事和游戏内功能。职业差异通过服装剪影、工具、姿态和色彩表达，不通过武器表达。

玩家角色的基础动作包括 `idle`、`walk`、`run`、`work`、`sleep`、`celebrate`、`sad` 和 `talk`；可选互动动作包括 `wave` 和 `jump`。动画以 30 FPS 为目标，循环动作应无缝衔接，动作过渡目标为 0.3 秒。NPC 需要至少支持待机、移动、对话和职业工作四类动作。

## 五、建筑与环境设计卡模板

每栋建筑应提交正面、侧面、等距三视图，入口/门、可交互点、产出点、碰撞体、升级前后差异和夜景灯光说明。建筑升级不得只改变数字，应通过屋顶、门头、灯带、幕墙、招牌、绿化或公共空间细节表现商业成长。住宅、商业、生产和公共建筑使用不同的轮廓语言，避免把所有建筑制作成同一套玻璃盒子。

环境资源应标明可行走、不可行走、可交互和装饰四类状态。道路必须提供导航边界，植被与路灯应有低面数远景版本，天气特效不得遮挡核心交互。城市地图优先使用建筑、银行、商业店铺、生产设施、NPC 和资源节点等品牌化图标，而不是没有语义的色块。

## 六、PBR、LOD 与纹理规范

所有可进入运行时的模型使用 PBR 材质。推荐纹理通道为 Base Color、Normal 和 ORM；发光材质仅用于夜景灯带、UI 标识和稀有交互点。金属、玻璃、混凝土、冰雪和植被应使用项目内 `pbrMaterialPresets` 作为初始参数，再由美术根据实物参考调整。

纹理运行时优先使用 KTX2 或 WebP，并保留 mipmap。预算门禁为 1K 不超过 2MB、2K 不超过 8MB、4K 不超过 24MB；PNG/JPG 可作为源文件，但不应直接作为运行时最终纹理。LOD 至少包含近景、中景和远景策略，模型需要提供可解释的面数变化，不得在近景突然丢失碰撞或关键轮廓。

| 资产类型 | LOD0 | LOD1 | LOD2 | 碰撞体 |
|---|---:|---:|---:|---|
| 玩家角色 | 15k–25k | 8k–15k | 3k–8k | 胶囊/简化身体体积 |
| NPC | 10k–20k | 5k–12k | 2k–6k | 胶囊或简化身体体积 |
| 建筑 | 5k–15k | 3k–8k | 1k–4k | 盒体/凸包组合 |
| 环境道具 | 预算内 | 50%–70% | 20%–40% | 只保留玩法相关碰撞 |

## 七、文件命名与目录

文件名使用小写 kebab-case，禁止空格、中文和版本混写。建议格式为 `{domain}-{asset-id}-{variant}-{lod-or-map}.{ext}`，例如 `character-merchant-01-lod0.glb`、`building-bank-upgrade02-lod1.glb`、`building-bank-basecolor-2k.ktx2`、`npc-doctor-idle.glb`。目录按照 `characters/player`、`characters/npcs`、`buildings/residential`、`buildings/commercial`、`buildings/production`、`buildings/public`、`environment/props`、`environment/weather`、`materials`、`ui` 和 `documentation` 划分。

资产提交必须同时附带 manifest 记录、预览图、技术规格、授权来源、变更说明和验收状态。未通过状态只能为 `catalogued` 或 `pending-import`；只有真实文件、PBR、LOD、碰撞体、纹理、动画和性能测试均通过后，才能标记 `verified`。

## 八、验收表

| 检查项 | 通过标准 | 证据 |
|---|---|---|
| 视觉 DNA | 半写实卡通、现代都市、冰雪商业语义一致 | 三视图/等距图/夜景图 |
| Logo 与颜色 | ISC Logo 使用官方组件，主色与功能色符合规范 | UI 截图与资源引用 |
| 模型规格 | 面数、骨骼和轮廓在资产类别预算内 | 导出报告 |
| PBR | Base Color/Normal/ORM 通道正确，材质响应稳定 | 材质球截图与纹理清单 |
| LOD | 近中远景切换稳定，关键轮廓不跳变 | 运行时录屏/指标 |
| 碰撞 | 可走、不可走、交互边界与地图逻辑一致 | 碰撞体预览 |
| 动画 | 30 FPS、命名正确、循环无跳变、过渡平滑 | 动画导出报告 |
| 性能 | 纹理大小、压缩、mipmap、内存和移动端预算通过 | textureOptimization 报告 |
| 运行时 | manifest 标记 verified，加载失败有诚实回退 | assetReadiness 报告 |
| 可用性 | 16:9 横屏、44px 触控目标、关键文本可读 | 多设备截图 |

## 九、当前交付边界

本工具包已经完成生产规则、概念方向、命名和验收门禁，可直接交给美术团队开始制作。当前项目仍没有真实玩家、NPC、建筑和环境 GLB/贴图/动画文件，因此不能把 3D 建模、绑定、纹理库交付或最终资产验收标记为完成。美术文件进入项目后，应先存放于规定的资产存储位置，更新 manifest，再运行 readiness、纹理、动画和 Babylon.js 运行时回归验证。
