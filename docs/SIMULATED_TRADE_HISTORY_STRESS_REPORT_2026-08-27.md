# 模拟交易历史面板压力测试报告

**作者：Manus AI**  
**日期：2026-08-27**  
**环境：local-hardhat / Vitest + jsdom / React 19**

## 测试目标

本次测试用于验证模拟环境下大批量订单进入交易历史面板时的渲染、状态筛选和手续费聚合行为。测试数据完全由本地可复现生成器创建，不代表真实主网交易，也不用于推断生产网络吞吐量。

## 测试配置与结果

| 指标 | 结果 |
|---|---:|
| 模拟订单数 | 1,200 |
| 订单类型 | SELL / BUY_OFFER 交替生成 |
| 状态覆盖 | COMPLETED / PENDING / CANCELLED |
| 初次可见行数 | 50 |
| 状态筛选可见行数 | 50 |
| 渲染与筛选测试耗时 | 821 ms |
| 手续费精度 | 6 位 micro-ISC 整数运算 |
| 60/40 分配余数 | 0 micro-ISC |
| 压力测试用例 | 2/2 |
| TypeScript 检查 | 通过 |
| 384MB 生产构建 | 通过 |

## 实施要点

面板不再一次性把全部历史订单挂载到 DOM，而是使用分段渲染：首次最多显示 50 笔，用户通过“加载更多”逐段增加。状态筛选会重新从过滤结果的第一页开始，并清除已展开的订单，避免大列表状态残留。筛选按钮增加 `aria-pressed`，使状态提交能够被自动化测试和辅助技术准确识别。

手续费不使用 JavaScript 浮点数累加。压力数据以 6 位 micro-ISC 最小单位转换为 `BigInt`，再按 6000/4000 BPS 分配至国库和营销钱包。测试同时断言总手续费等于两个分配项之和，且分配余数为零，因此本次 1,200 笔数据不存在累计浮点漂移。

## 验证范围

压力测试覆盖了 1,200 笔可复现模拟记录的生成、状态统计、初次渲染、PENDING 状态筛选和手续费汇总。配套单元测试覆盖金额转换、小数位上限、订单唯一标识、状态计数和 60/40 聚合。完整目标测试共 5 项通过。

## 限制与解释

821 ms 是当前沙箱的 jsdom 测量值，不是移动设备或真实浏览器的基准，也不代表链上并发吞吐量。模拟记录使用固定本地数据生成，不包含真实 RPC 延迟、钱包签名、区块确认或数据库写入。真实合约仍处于 Draft 状态，未执行主网或测试网写入；该压力测试不能替代第三方安全审计、链上压测或真实设备性能测试。
