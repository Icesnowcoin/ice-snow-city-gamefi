# 凭据安全与仓库扫描

项目不在源码、文档、测试夹具或前端包中保存 GitHub Token、私钥或外部 API 密钥。运行时配置必须通过项目安全密钥管理注入，前端只允许使用明确设计为公开的配置。

仓库中的 `scripts/scan-secrets.sh` 只扫描当前已暂存版本的高置信度凭据模式，包括 GitHub Token、常见私钥头、AWS Access Key、Slack Token 和 Google API Key。`.github/workflows/secret-scan.yml` 会在 push 和 pull request 时执行该检查，并在发现匹配时阻断流程。

该扫描不会清除历史提交，也不会自动使用或撤销历史令牌。若凭据曾经出现在 Git 历史、日志或外部同步记录中，必须由凭据持有人在对应平台立即撤销并轮换；清理提交历史不能替代撤销操作。

扫描规则刻意只覆盖高置信度模式，以避免把普通文档中的“token”文字或链上地址误判为凭据。新增第三方服务时，应在代码评审中补充相应模式和最小权限说明。
