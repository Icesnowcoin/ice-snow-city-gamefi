# Ice Snow City Seaport 风格 NFT 市场草案

## 目标与范围

`contracts/ISCSeaportStyleMarketplaceDraft.sol` 是一个面向 Ice Snow City 的最小固定价 NFT 市场草案。它借鉴 OpenSea Seaport 的关键安全思想：订单由卖家离线签名，链上根据 EIP-712 结构化数据重建订单哈希，使用 nonce 和订单哈希防止重放，并在同一笔交易内完成 ISC 支付与 NFT 转移。

本草案**没有复制** Seaport 的复杂 consideration、criteria、zone、conduit、批量订单、部分成交和高级回调系统。这样做是为了先建立可审计的最小状态机，降低游戏市场的攻击面。后续如需扩展拍卖、批量订单或部分成交，应单独设计和审计，而不是直接拼接代码。

## 订单生命周期

| 阶段 | 执行者 | 链上动作 |
| :--- | :--- | :--- |
| 创建 | 卖家前端 | 构造订单并使用钱包签名，不发送交易 |
| 授权 | 卖家/买家 | 卖家批准 NFT；买家批准市场合约使用 ISC；双方各自承担 Gas |
| 结算 | 买家 | 提交订单和签名，合约验证签名、过期时间、nonce 和订单状态 |
| 原子转移 | 合约 | 先锁定订单，再从买家转 ISC 给卖家/国库，最后安全转移 ERC-721 或 ERC-1155 |
| 结果确认 | 前端/索引器 | 监听 `OrderFulfilled`、`OrderCancelled` 和 `OrderNonceCancelled` 事件 |

## 订单哈希与签名

EIP-712 域使用名称 `Ice Snow City Seaport Style Marketplace` 和版本 `1`。订单结构包含卖家、NFT 合约、Token ID、数量、价格、过期时间、nonce、资产类型和 salt。`salt` 让卖家可以为相同资产和 nonce 创建不同的订单，`nonce` 则支持按卖家撤销一组订单。

订单必须满足：卖家和 NFT 合约地址非零、价格大于零、过期时间晚于当前区块时间；ERC-721 数量必须为 1，ERC-1155 数量必须大于 0。签名恢复地址必须与 `offerer` 一致，买家不能购买自己的订单。

## 费用与 ISC 边界

本草案只对市场成交价收取 10% 市场佣金，90% 发送给卖家，10% 发送给国库地址。该规则不代表 ISC 代币本身有税收或控制逻辑，也不适用于 NFT 铸造和社交消费。NFT 铸造的 1%销毁、69%国库、30%营销必须由独立铸造合约实现；社交消费的 60%国库、40%营销也必须由其业务模块实现。

ISC 是已放弃所有权、代理和控制权的普通 ERC-20。市场合约只调用普通的 `transferFrom`，不会暂停、升级、增发、修改 ISC 税率或从 ISC 合约侧强制扣款。买家必须在执行订单前主动批准市场合约使用足额 ISC，且玩家承担批准和成交交易的 Gas。

## 当前安全边界与未完成门禁

这是**合约草案**，不是已部署或已审计合约。当前仓库没有为该 Solidity 草案提供完整 Hardhat/Foundry 编译门禁，因此在测试网部署前必须固定 Solidity 版本、OpenZeppelin 版本、优化设置和构造参数，并完成编译、单元测试、模糊测试、重入/回调测试、签名边界测试、Gas 评估、区块浏览器验证和第三方审计。

还需要重点审计以下问题：NFT 合约是否在成交期间转移或销毁资产；ERC-721/ERC-1155 接收回调和恶意返回数据；ERC-20 非标准返回值；卖家撤销后的竞态；订单过期边界；链上时间依赖；佣金舍入；恶意 NFT 合约回调；以及订单取消事件和索引器状态的一致性。

## 前端集成建议

前端应先读取订单摘要并展示卖家、资产、价格、佣金、Gas 估算和授权状态。用户必须分别确认 NFT 授权、ISC 授权和成交交易。服务端可以存储公开订单和索引事件，但不能代替用户签名，也不能返回虚假的成功交易哈希。若没有配置已部署市场地址和最终 ABI，TradingCenter 应继续展示诚实的未配置状态并禁用链上成交按钮。
